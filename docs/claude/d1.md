# D1・保存・暗号の決まり（D1・migrations・設定の保存・トークンに触るときだけ読む）

- **保存してよいのは、Re:Mail 上の設定（ピン留め・非表示・名前変更・グループ・フィルター・共通設定・アカウント設定）と、暗号化したトークンだけ。** メールの中身を保存する列・JSON を作らない。メールを指すときは Gmail のメッセージ ID だけを持つ。
- スキーマは `migrations/` の連番ファイルで管理し、デプロイ時に Actions が `wrangler d1 migrations apply` で当てる。適用済みのファイルは書き換えず、変更は新しいファイルで足す。
- スキーマ変更は非破壊にする（`DROP TABLE` を書かない、列は `ALTER TABLE ... ADD COLUMN`）。新しいコードより先にスキーマが当たるので、ロールバック先の古いコードが壊れない形にする。列・データを消すときは、使わなくなるコードを先に出し、次の段階で消す（2段階）。
- 保存の形の移行は 2026-10-23 にすべて終え、古い形式のデータと読むコードは消した。今のコードは今の形式だけを読む。また形を変えるときは、段階1（新しい形も読める）→段階2（新しい形で書く）→古い形式のデータと読むコードを消す。
- この環境からは本番 D1 を直接操作しない。migrations を足して push し、Actions に当てさせる。
- `chat_configs` の `account_email` が `""` の行は `__GLOBAL_SETTINGS__`（共通設定）/ `__ACCOUNT_SETTINGS__`（アカウント設定）用に予約している。中身は暗号化する。
- `linked_accounts` のトークンは必ず `tokenCrypto.ts` の `encryptSecret` / `decryptSecret` を通す。
- 鍵（`TOKEN_ENCRYPTION_KEY`）が無いときは暗号化・復号・HMAC のどれも例外にし、API は 500 を返す。平文で保存する逃げ道を作らない。鍵を変える・消す前提のコードを書かない（`encv1:` のデータが読めなくなり連携が全滅する）。鍵を足す・更新するなら新旧どちらの形式でも読めるようにする。
- 設定の保存の送り直しは `configSaveQueue.ts`（何度送っても結果が同じなので自動で送り直す。送信とは違う）。
